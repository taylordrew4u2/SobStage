# SobStage v1.13.29 — release candidate

SobStage records up to eight external microphones at once, each to its own
file plus a summed mix, and sends one low-latency monitor mix to everyone in
the room. This release stops a slow SD card from blocking Record while this computer has room, and gives the cameras their own settings page.

> **This is a release candidate, not a general release.** Physical-hardware
> validation is still open. See **Known limitations** below and
> [`RELEASE_CHECKLIST.md`](https://github.com/taylordrew4u2/usbmic/blob/v1.13.29/RELEASE_CHECKLIST.md) before you trust it with
> a recording you can't repeat.

## Downloads

| File | For |
|---|---|
| `SobStage-macOS.dmg` | macOS 13 or later, Apple silicon and Intel. Open it and drag SobStage onto Applications. |
| `SobStage-macOS.zip` | The same app, without the disk image. |
| `SobStage-Windows.zip` | Windows. Portable: unzip and run `bin\SobStage.exe`. No installer. |
| `SobStage-Linux.zip` | Linux (early use; not a v1 production target). |
| `SobStage-1.13.29-source.zip` | The exact SobStage and JUCE source this release was built from (GPLv3). |
| `SHA256SUMS` | Checksums for every file above. |

This release is not code-signed with a Developer ID or Authenticode
certificate, the same as every release before it. On macOS, after dragging the
app to Applications, run this once in Terminal before the first launch,
otherwise Gatekeeper says the app "is damaged":

```sh
xattr -dr com.apple.quarantine "/Applications/SobStage.app"
```

On Windows, SmartScreen shows "unknown publisher" on first run. Choose
**More info → Run anyway**. Verify the download against `SHA256SUMS` first.

To check a download, keep it beside `SHA256SUMS` and run this on a Mac. The
[install guide](https://github.com/taylordrew4u2/usbmic/blob/v1.13.29/docs/INSTALLING.md#download)
has the Windows and Linux commands.

```sh
grep ' SobStage-macOS.dmg$' SHA256SUMS | shasum -a 256 -c -
```

## What's new

**A slow SD card no longer stops you recording.** With room on this computer
for an hour of recording plus 2 GB, every take is recorded here and copied to
the card after Stop, and the card's speed isn't checked at all. Before, SobStage
wanted room here for everything the card could hold -- about 130 GB beside a
128 GB card with a camera on -- and short of that it sent the take to the card,
said the card was too slow, and kept Record off.

- With less than an hour of room here, a card that passed its check takes the
  take. A card that is too slow, full, locked, or FAT32 with a camera never
  stops you while this computer has room for 10 minutes: the take records
  here, and the line under Record says how long you have.
- The card's speed check stops as soon as the card proves too slow, instead
  of writing all 200 MB (minutes on a slow card).
- A take recorded here stops with 1 GB still free, after warnings at ten and
  two minutes, so the computer keeps working and the copy can run.

**Cameras has its own settings page.** **Cameras** is in the bar at the top,
between Help and Settings. It opens beside the main screen, so the pictures
stay in view. For each camera: its name, whether it records, the file it
writes, its **Picture size**, and (on a Mac) what it is running at. It also
says how much space an hour of recording takes. "Also save video with the
sound in one file" moved here from Settings.

**Before a show:** set your microphones and headphones to the same sample rate
as SobStage in **Audio MIDI Setup** (48 kHz is safest), allow the microphone
prompt, and make a short test take.

Everything in [v1.13.28](https://github.com/taylordrew4u2/usbmic/releases/tag/v1.13.28) is included.
Full list: [`CHANGELOG.md`](https://github.com/taylordrew4u2/usbmic/blob/v1.13.29/CHANGELOG.md).

## Known limitations

- **No completed take from physical microphones has passed the release
  hardware matrix yet**, on any platform. The engine is covered by 878 unit
  tests and by simulated CoreAudio and WASAPI device layers, but simulation is
  not hardware certification.
- **Pulling the card mid-take** is handled in code, and an automated test
  makes the recording folder stop answering inside the real app at Record and
  at Stop. It has not yet been tested by pulling a real card on macOS or
  Windows.
- **HDMI capture cards:** v1.13.13 and v1.13.14 added an all-black-picture
  warning, a wait for the camera prompt and 30 fps mode selection on the Mac,
  but a visible preview and a completed camera recording are still unverified
  on real hardware.
- **Headphones on each microphone (Mac):** the shared mix through the combined
  SobStage device has not been latency-measured on hardware, and a mic with
  built-in direct monitoring (such as a Blue Yeti) plays its owner's voice
  twice.
- **Phones and wireless receivers that present as ordinary USB audio** can't be
  told apart from an interface, so they may appear as inputs.
- **Monitor latency** has not been measured by loopback on real hardware.
- **Linux** is for early use and testing only.

## Updating and rolling back

There is no automatic update. Download the new version and replace the old
one. Your settings, microphone names and recordings are kept.

If this version causes you a problem, the previous release,
[v1.13.28](https://github.com/taylordrew4u2/usbmic/releases/tag/v1.13.28),
remains available. Back up `settings.json` before you downgrade. Rolling back
never deletes recordings.

## Support and privacy

- Report a problem: [open an issue](https://github.com/taylordrew4u2/usbmic/issues/new).
  **Settings → Export diagnostics** creates a zip of logs, recent session
  details and device names. It never contains audio or video. Read it before
  posting it publicly.
- SobStage sends nothing unless you switch on **Check for updates** (off by
  default) or press **Check now**. Either one asks GitHub's public releases
  API for the latest version number, with no identifier, settings, logs or
  recordings. There is no crash upload, analytics or automatic update. See
  [`PRIVACY.md`](https://github.com/taylordrew4u2/usbmic/blob/v1.13.29/PRIVACY.md).
